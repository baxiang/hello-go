# 性能优化

## 指标优化

### 减少时间序列数量

```yaml
# 避免
http_requests_total{user_id="12345"}  # 高基数

# 推荐
http_requests_total{user_type="premium"}  # 低基数
```

### 合理使用标签

```yaml
# 好的实践
http_requests_total{method="GET", status="200"}

# 避免过多标签组合
# 10个标签，每个10个值 → 10^10 时间序列
```

### Histogram 优化

```go
// 合理设置桶
prometheus.NewHistogram(prometheus.HistogramOpts{
    Name:    "http_request_duration_seconds",
    Help:    "HTTP request duration",
    Buckets: []float64{.01, .05, .1, .5, 1, 5},  // 不要太多
})
```

## 抓取优化

### 抓取间隔

```yaml
global:
  scrape_interval: 15s  # 默认，根据需求调整

scrape_configs:
  - job_name: 'critical'
    scrape_interval: 5s   # 重要服务高频
  
  - job_name: 'batch'
    scrape_interval: 60s  # 批处理低频
```

### 超时设置

```yaml
scrape_configs:
  - job_name: 'app'
    scrape_timeout: 10s
    scrape_interval: 15s
```

### 样本限制

```yaml
scrape_configs:
  - job_name: 'app'
    sample_limit: 50000  # 限制每个抓取的样本数
```

## 查询优化

### 避免范围查询过大

```promql
# 不推荐：大范围
rate(http_requests_total[1h])

# 推荐：适当范围
rate(http_requests_total[5m])
```

### 使用 Recording Rules

预计算复杂查询。

```yaml
groups:
  - name: example
    interval: 30s
    rules:
      - record: job:http_requests:rate5m
        expr: sum by (job) (rate(http_requests_total[5m]))
```

### 查询示例优化

```promql
# 慢查询
sum(rate(http_requests_total[5m])) by (job) / 
sum(rate(http_requests_total[5m] offset 1h)) by (job)

# 优化：使用 recording rule
# 预计算 rate
- record: job:http_requests:rate5m
  expr: sum by (job) (rate(http_requests_total[5m]))

# 查询使用预计算结果
job:http_requests:rate5m / 
job:http_requests:rate5m offset 1h
```

## 最佳实践

1. **控制时间序列数量**：< 1000万
2. **合理设置抓取间隔**：根据重要性调整
3. **使用 Recording Rules**：预计算复杂查询
4. **监控 Prometheus 自己**：关键指标告警
5. **长期存储**：使用 Thanos/Cortex/VictoriaMetrics
6. **资源规划**：
   - CPU: 2-4核
   - 内存: 8-16GB
   - 磁盘: SSD，根据保留时间规划
